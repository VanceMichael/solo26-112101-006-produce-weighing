# 番薯上门收购的跨秤补票和换箱结算

秤站清单 `/scales` 提供站点与当前可补传的字节片段。线路按 UTF-8 NDJSON 记录原始票据，片段可从任意字节开始，字段 `offset` 是该流的绝对字节偏移，`bytes` 为长度。相邻或重传可能重叠，服务器仅提供所列地址。记录唯一身份为设备、开机期和原始称量号。票据类型为 `gross`、`tare`、`reprint`、`void`。 `replaces` 是同设备世代内的原票号，金额及重量用十进制输入。空箱与满箱的时间可早于归档时间。
 
车队登记由 `/fleet/movements` 提供。整趟车有卸空交接，票据的 `movement` 绑定对应装载或正式换箱。有效的核准由 `/desk/approvals` 提供，其中 `supersedes` 记录允许核准的原票，价格为每公斤元。演练值班是同一车队，但跨年月日不重置车次身份。

## 本地来源

资料均为合成记录。Node.js 22 环境下执行 `npm ci`，再用 `npm run sources` 启动，默认监听 `127.0.0.1:4180`。可用环境变量 `PORT` 修改端口。在容器中运行时，服务和访问端处于同一网络命名空间。

`data/sources.json` 保存原始报文及站点页面。连续响应由来源按同一进程内的观察次数提供。阶段从 `initial` 启动，本地演练人员可用 `POST /scenario/阶段名` 切换，未覆盖的路由延用初始响应。切换不清空来源的请求记录。重开服务会复位。

执行 `npm test` 核对来源契约。依赖锁仅包含 Node.js 标准库运行所需的项目清单。容器方式可先执行 `docker build -t produce-weighing-sources .`，再执行 `docker run --rm produce-weighing-sources`。镜像准备完成后的验证不需要外网。

## 留存确认

对站端确认 `POST /scales/farm/ack` 发送流号和半开区间终点 `through`。确认端点取最后一份可以在柜面独立重放的完整票后面的字节位置。站端也可自行报告由于滑动缓存而丢失的区间。 `GET /scales/retention` 返回分流留存起点，收到响应超时后可查站端实际应用到哪。确认只表示站端原始传输交付，后续柜面仍按票据业务规则审核。

## 柜面采集与结算（`src/`）

柜面程序把秤站字节流、车队装卸单和柜面核准收成一份可逐户核实的买入结算账。仅使用 Node.js 标准库，状态默认落在 `state/desk.json`（可用 `STATE_FILE` 覆盖），来源地址用 `SOURCE_URL` 覆盖。

命令行（`npm run desk -- <命令>`）：

| 命令 | 作用 |
| --- | --- |
| `run` | 采集当前阶段可见来源并结算；可重复执行，字节按偏移合并、票据按身份去重、凭据按证据指纹决定是否新开 |
| `status` | 逐户逐车逐箱的核对结论、停箱原因、票据冲突与解析异常 |
| `retention` | 拉取站端留存起点，列出仍可补的缺口与已不可补区间 |
| `ack --stream <流号> [--through n] [--endpoint /scales/x/ack]` | 发送留存确认；默认只确认本地能独立重放的完整票前缀，半张票/字节缺口拒绝确认 |
| `vouchers` | 全部凭据（原票、续票、冲正、补差）及各自引用的票据身份 |

`npm run desk:server` 启动只读柜面 HTTP 服务，路由：`/statements`（农户对账单与净应付）、`/lines`、`/trucks`（整车补传窗口是否仍开放）、`/vouchers`、`/tickets`（含重复送达份数、冲突、解析异常）、`/retention`（覆盖、缺口、确认历史）。

### 业务规则落地

- **票据身份**：`设备|开机期|原始称量号`。补打（`reprint`）是同一称量，重复认领不产生新事实；同身份读数/箱体/装卸关系不一致登记为冲突。
- **作废与替换**：`void` 显式作废后，原称量挂起；替换票必须在 `/desk/approvals` 中有同身份核准且 `supersedes` 回指被替换票才生效，未核准读数不能覆盖争议来源。
- **皮重适用范围**：皮重按 `movement` 绑定同一次卸空与对应箱体，不按箱码跨车次套用；换箱后换箱前箱体的重量只进入追溯（`trace`），不得参与净重。
- **换箱校正**：换箱登记（源箱/目标箱/地点）到达后，需取得换箱后满箱替代称量，且同一次卸空由同一秤分别证明原箱与目标箱皮重，再经收购员核准才可结算。
- **凭据与冲正**：买入凭据以“户 + 车次”为单位。无争议箱可先签收，其余箱保留等待原因；已结算箱事后被停或证据变化时，原凭据保留可查，另开冲正（负差额）或补差（正差额），绝不重复发出等额凭据。
- **补传窗口**：车次下任一箱未核清，整车保持 `open`；采集从 `/scales` 公布的窗口要票，503/425 等失败留痕并在后续班次重试。
- **留存安全**：`safeThrough` 取留存起点之后连续完整行的终点；半行、行内缺口、留存起点切进的行都不会让站端删掉唯一副本。回执丢失（如 504）只记为待核实，下一班先用 `/scales/retention` 对齐；已越过留存起点的缺口列为“确实不可补”，与仍待核的结算分开。已签收凭据引用的票据字节始终保存在本地。

### 测试

`npm test` 同时运行来源契约测试与柜面单元/端到端测试（共 27 项）。端到端用例会在临时目录启动来源服务，依次切换 `initial → exchange → reviewed`，覆盖离线半行补传、重叠重传去重、换箱冲正与核准补差、留存确认超时和状态持久化。
